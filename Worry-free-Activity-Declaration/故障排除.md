# 🔧 故障排除指南

## 常见问题及解决方案

### 1. "启动失败，请确保在正确的页面上使用"

**问题描述**: 点击开始按钮时出现此错误

**可能原因**:
- 内容脚本没有正确注入
- 页面结构不匹配
- 插件权限不足

**解决步骤**:

1. **刷新页面**
   - 按 F5 刷新当前页面
   - 重新尝试启动插件

2. **检查页面是否正确**
   - 确保你在活动申报页面上
   - 页面应该包含商品表格

3. **检查浏览器控制台**
   - 按 F12 打开开发者工具
   - 查看 Console 标签页是否有错误信息
   - 输入 `testPageElements()` 检查页面元素

4. **重新加载插件**
   - 进入 `chrome://extensions/`
   - 找到"活动申报助手"
   - 点击刷新按钮重新加载插件

5. **检查插件权限**
   - 确保插件有访问当前页面的权限
   - 检查是否被浏览器阻止

### 2. 无法识别商品或价格

**问题描述**: 插件运行但没有勾选任何商品

**解决步骤**:

1. **检查品类配置**
   - 确认关键词是否正确
   - 确认最低价格设置合理

2. **测试页面元素**
   - 在控制台输入 `testPageElements()`
   - 检查返回的元素数量

3. **测试品类匹配**
   - 在控制台输入 `testCategoryMatch("商品名称", "关键词")`
   - 例如: `testCategoryMatch("袜子", "袜子")`

4. **检查页面结构**
   - 确认商品名称在 `.goods-info_title__yHBeG` 元素中
   - 确认价格在第5列

### 3. 插件图标不显示

**问题描述**: 浏览器工具栏中没有插件图标

**解决步骤**:

1. **检查插件是否安装**
   - 进入 `chrome://extensions/`
   - 确认插件在列表中且已启用

2. **固定插件图标**
   - 点击扩展程序图标（拼图图标）
   - 找到"活动申报助手"
   - 点击图钉图标固定到工具栏

3. **重新安装插件**
   - 删除现有插件
   - 重新加载插件文件

### 4. 配置不保存

**问题描述**: 配置的品类信息没有保存

**解决步骤**:

1. **检查存储权限**
   - 确认插件有 `storage` 权限
   - 检查浏览器是否阻止了存储

2. **重新配置**
   - 重新输入品类信息
   - 确认输入框有值

3. **检查控制台错误**
   - 查看是否有存储相关的错误信息

## 调试工具使用

### 控制台命令

插件提供了以下调试命令：

```javascript
// 测试页面元素
testPageElements()

// 检查插件状态
testPluginStatus()

// 手动触发检查
manualCheck()

// 测试品类匹配
testCategoryMatch("商品名称", "关键词")

// 显示帮助信息
debugHelp()
```

### 使用步骤

1. **打开开发者工具**
   - 按 F12 或右键选择"检查"

2. **切换到 Console 标签页**

3. **输入调试命令**
   - 例如: `testPageElements()`

4. **查看输出结果**
   - 根据结果判断问题所在

## 页面兼容性检查

### 支持的页面结构

插件需要以下页面元素：

```html
<!-- 表格行 -->
<tr data-testid="beast-core-table-body-tr">

<!-- 商品名称 -->
<div class="goods-info_title__yHBeG">商品名称</div>

<!-- 价格信息（第5列） -->
<td>¥价格</td>

<!-- 复选框 -->
<input type="checkbox">
```

### 检查页面结构

1. **打开开发者工具**
2. **检查元素**
   - 右键点击商品名称，选择"检查"
   - 确认类名为 `goods-info_title__yHBeG`

3. **检查价格元素**
   - 右键点击价格，选择"检查"
   - 确认在第5列的位置

## 性能优化建议

### 如果页面加载慢

1. **减少检查频率**
   - 修改 `content.js` 中的检查间隔
   - 默认是2秒，可以改为5秒

2. **限制处理行数**
   - 每次只处理可见的行
   - 避免处理大量数据

### 如果内存占用高

1. **清理已处理的行**
   - 定期清理 `processedRows` 集合
   - 避免无限增长

2. **优化DOM查询**
   - 缓存查询结果
   - 减少重复查询
